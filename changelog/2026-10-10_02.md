## Why care?

Plan 4 of the connector spec (`context-v/specs/MemoPop-Connector-API.md`). Until
now `add_materials` answered `not_implemented`, so a partner's Claude had to
paste the key facts from a deck into the conversation. Now Claude can hand
MemoPop the deck itself, and MemoPop reads it: `next_step` offers a brief of
what the materials claim before any research starts, and every section's
research starts from the company's own account. All seven materials IDs
(CONN-MAT-01 to 07) are GREEN; they were all RED, none missing, at the
TDD-floor commit.

## What landed

**`add_materials`, three ways in.** Pasted `text` (up to 100,000 characters,
else `material_too_large`) is saved and `ready` in the response. A `link` is
fetched by the server in the background. An item with only a `filename` is
`queued` and the call returns an `upload_url`. The call returns at once in every
case (CONN-MAT-04 holds it under 5 seconds with a ~1 MB deck behind a link that
doesn't answer until the test releases it). The same text or link on the same
deal is the same material, so a repeated call stores nothing twice.

**Link fetching** (`src/connector/materials/fetch.py`): `httpx` with timeouts, a
100 MB cap, five redirects at most, and a guard on every request, redirects
included, that refuses private, loopback, link-local, and reserved addresses, so
a link can't point the server at its own metadata endpoint. Google Drive file
links, Google Docs, Sheets, and Slides, and Dropbox links are rewritten to their
direct-download or export form. DocSend is refused before any request, with a
message telling the partner to upload the PDF.

**The upload page** (`/upload/{token}`): `GET` serves a minimal HTML form, `POST`
takes the files. Tokens are 256-bit random, stored only as their SHA-256 under
`<MEMO_IO_ROOT>/.uploads/`, single use (spent by an atomic rename), and expire
after an hour. Unknown is 404; used or expired is 410; a post with no file is
400 and leaves the token usable. Files match the waiting materials by name,
then in order; extra files become materials of their own.

**Extraction** (`src/connector/materials/pipeline.py`, the `materials.extract`
server step): originals go to the firm's bucket under
`materials/<material_id>/<filename>`; text goes to
`deals/<deal>/materials/<material_id>.md`, cut at 400,000 characters. PDFs,
Word, Excel, CSV, PowerPoint, markdown, and text go through the orchestrator's
own `src/agents/dataroom/document_text.py` (PyMuPDF first, OCR for scans); a web
page goes through BeautifulSoup. Every job ends `ready` or `skipped`, so
`materials_pending` always drains. A link or file that can't be read becomes a
`material_unreadable` skip, which `next_step` reports once and `list_deals`
lists; the deal goes on to research.

**`materials.brief`** now carries an instruction adapted from `deck_analyst.py`'s
analysis prompt, minus the model call: the same fields, only what the materials
state, exact figures, every claim marked `[^deck]` (or its kind). CONN-MAT-07
shows `next_step` handing it out, with the material's text as input, before
the first section's research.

**Docs**: the tool's three examples (pasted notes, a deck by filename, a
non-http link) run in CONN-DOCS-01; the API changelog has a 1.1.0 entry.

## Decisions a reviewer should know

- **A third material status, `skipped`.** Phase 1 fixed the record as
  `{material_id, kind, status: queued | ready}`. A material that can't be read
  must leave `queued` or `materials_pending` never drains, so it becomes
  `skipped` (with `error`). Nothing was renamed or removed; the record also
  gains `source`, `title`, `filename`, `link`, `bucket_key`, `bytes`, `chars`,
  `added_at`, `ready_at`, and `awaiting_upload`.
- **Skips carry `material_id`.** A material skip is recorded as
  `{step_id: materials.extract, code: material_unreadable, reason, material_id}`.
  `list_deals` shows the code and the reason (which names the file or link),
  not the id, since its skip shape is plan 1's.
- **`link_unreachable` is for links that can't be fetched at all** (not http or
  https), refused before anything is saved. A link that is merely down is a
  skip, per the plan.
- **Pasted text has no bucket original.** The text is the original; it lives in
  the workspace only.
- **`document_text.py` is loaded by file path**, not through
  `src.agents.dataroom`, whose `__init__` loads `.env` and imports the agents
  that call models.
- **Pending materials don't hold research back.** `materials.brief` is offered
  once some material is ready; while a link is still being fetched, `next_step`
  hands out research, and the brief comes up as soon as a material is ready.
  That is plan 1's `flow.walk`, unchanged.

## What was not tested

No test touched the real internet: every link is served by an
`httpx.MockTransport`, which bypasses the private-address guard, so the guard is
tested only as a function (and as installed on the real client), never against
real DNS; it also checks the address at resolution, not at connect, so DNS
rebinding is not ruled out. No real Google Drive, Dropbox, or DocSend link was
fetched, so the rewritten URLs match their documented forms but not a live
response (Drive's virus-scan interstitial for large files would be read as
HTML). OCR was never exercised: the synthetic decks have a text layer. The S3
bucket still has no test; originals were written only to the local-directory
bucket. Background jobs run in the server process, so a restart while a link is
being fetched leaves that material `queued` for good, and an upload link that
expires unused leaves its materials `queued` too; neither is swept yet. The
upload page was driven through FastAPI's test client, not a browser. The
`materials.brief` instruction has never been run by a model. Nothing was
deployed.
