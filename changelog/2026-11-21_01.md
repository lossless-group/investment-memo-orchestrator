```
fix(citations): Resolve each section's citations against its own research

Each section's research file numbers its sources from 1, but final assembly
treated citation keys as global, so every section's [^25] took whichever
source was defined as [^25] first. assemble_citations() now pairs each
section with its own research file and consolidates through
consolidate_citations(), as the connector's compile already does.

A guard follows every citation in the assembled output to its source and
logs a warning when that source isn't in the section's research file.

Also included: consolidate_citations() takes optional per-text definitions;
renumber_citations() is documented as global-key and left for
cli/assemble_draft.py.
```

## Why Care?

A citation is how a reader checks a claim. In the first case, a memo citing about 70 distinct sources came out with 34, and a claim sourced to the company's own pro forma linked to an unrelated press release. Every memo the local pipeline assembled in codified mode had this problem, and nothing in the run log showed it. The memos the uploader sends to the server become compiled version 1, so they need correct citations before they go up.

## What's New?

- **Section-local keys.** `assemble_citations()` in `src/agents/citation_assembly.py` reads `2-sections/X.md` with `1-research/X-research.md` (the same name `writer.py` reads), and passes every section through `consolidate_citations()`. A definition the section carries itself wins over its research file's. Sources are still numbered 1..N by first appearance, one number per link, and `merge_duplicate_definitions()` is still the last pass.
- **No global fill.** The first-come fill of definitions from every `1-research/*.md` is gone from final assembly.
- **A section with no research file.** `header.md`, or a section without a matching research file, borrows a definition only when every research file that defines the key agrees on its source. An ambiguous key stays undefined and is reported as missing, so it can't quietly take another section's source.
- **A guard in the run log.** After consolidation, each citation in a section's assembled text is followed to its definition. If that source isn't one the section's research file defines, the log prints a warning naming the section and the original key, and `research_mismatches` in the result lists them. Sections with no research file are listed as unchecked.
- **Section files keep their definitions when research doesn't have them.** A section's own `[^X]:` definitions are stripped from disk only when its research file defines the same key with the same source.
- Tests: `tests/test_citation_collisions.py` (two sections sharing `[^25]` for different sources, the guard both ways, and both no-research-file cases).

## Not Tested, and Still Open

- Not run against a real memo in this change: the tests use a synthetic two-section output directory. Rebuilding the memos assembled before this fix (plan steps 4 and 5) is the next step and reads firm data, so it runs separately.
- `cli/assemble_draft.py` still calls `renumber_citations()`, which treats keys as global. It also concatenates sections without applying the renumber map. It should move to `assemble_citations()`; that is outside this change.
- `context-v/issues/Final-Draft-Citations-Collide-Across-Sections.md` stays open until the affected memos are repaired.
