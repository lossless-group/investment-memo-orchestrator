## Why care?

This is plan 7 of the connector spec (`context-v/specs/MemoPop-Connector-API.md`).
Without a skill, Claude has to work out MemoPop's method from tool names. The
plugin puts the connector and a short skill in one install, so Claude starts
with `list_deals`, follows `next_step`, shows the partner each section's research
before drafting, says one line about a skipped step, and stops on `down`.

## What landed

**The plugin** (`plugin/`). Its layout follows Claude's *Plugin structure and
testing* page: the manifest alone in `.claude-plugin/plugin.json` (name `memopop`,
version `0.1.0`), `.mcp.json` pointing at `https://memopop.didi.sh/mcp` with no
credential in it, `skills/memopop/SKILL.md`, and a README of more than 40 words.
There is no top-level `bin/`, because that stops claude.ai and Cowork from
installing a plugin. `claude plugin validate plugin` passes (Claude Code 2.1.286).
No build step is needed: you zip the folder and upload it in **Customize > Plugins**.

**The skill** is under 250 words, frontmatter included. It states the spec's rules: a multi-step pipeline
with an artifact trail; start with `list_deals`; always call `next_step` and do
only what it says; show every research file and wait for approval; submit with
`partner_approved: true` only after approval; one line on `skipped`, then
continue; stop and tell the partner on `down`.

**CONN-PLUG-01** checks each rule appears inside a single sentence or bullet, so
scattered words can't pass it. A guard test feeds it those words scattered across
sentences and confirms every rule fails. It also checks the skill stays under 450
words and that its name matches its folder.

**CONN-PLUG-02, the real-Claude run** (`tests/connector/test_real_claude.py`,
harness in `tests/connector/real_claude.py`). It uses the Messages API's MCP
connector (`mcp_servers` plus a `mcp_toolset` tool, beta `mcp-client-2025-11-20`)
called over plain `httpx`, so no new dependency. The skill is the system prompt,
and a scripted partner approves research only once Claude has shown it. It runs
only when `ANTHROPIC_API_KEY`, `MEMOPOP_LIVE_URL`, and `MEMOPOP_HEALTH_KEY` are all
set. Otherwise it is skipped, which the ledger reports as GATED. The model
defaults to `claude-haiku-5-5`, and requests are capped at 24. A preflight checks
the key and the outline before any token is spent. The checks read the server's
tool results and, after the run, its REST state (phase, skips, which artifacts
exist). The only prose checks are the two rules that are about prose: research
shown before approval, and the skip mentioned.

**The checks are proven offline.** `ScriptedModel` answers payloads the way the
API does (`mcp_tool_use`, `mcp_tool_result`, and `pause_turn` blocks) against a
local server's `/mcp`. A run that follows the method passes every check. Each of
three broken behaviours is caught: approving without showing, ignoring the skip,
and calling tools after `down`. A server without the fault hook gives a run that
the checks fail for having no skip and no down.

**A test-only fault hook** (`src/connector/faults.py`). The real run needs the
server to skip one step and to go `down` once. `MEMOPOP_DISABLED_STEPS` is
server-wide and would affect real firms, so it was not used. The hook fires only
when both of these hold:

1. The firm is listed in the new `MEMOPOP_FAULT_FIRMS` (empty by default).
2. The deal's outline is in the firm's own folder and has a `test_faults` block.

The `real-claude-three` outline turns off `research.sources` (a `step_disabled`
skip) and makes `next_step` return `service_unavailable` at `enhance.tables`,
before anything is written. A run therefore ends after the three drafts, which
keeps it cheap. MemoPop's shared outlines never fire the hook. Required steps
are never skipped by it, and a malformed or unreadable block counts as no
faults. `python -m src.connector.faults install-outline test-firm` installs
the outline. Nine tests cover these guards.

**Operator guide** (`docs/operator/connect-claude.md`) covers:

- adding the connector by URL in Claude Desktop
- what the partner sees: didi.sh sign-in, then a consent screen to pick their firm
- installing the plugin
- the one-time server setup and the exact command for the real run

**Ledger.** At the test commit, CONN-PLUG-01 was RED and CONN-PLUG-02 was GATED,
with none missing. Now CONN-PLUG-01 is GREEN and CONN-PLUG-02 stays GATED until
it is run against the deployed server. The plan's status is `Gated-On-Deploy`,
not `In Progress`, because `--active-plans --require-green` would otherwise fail
`scripts/check.sh` on the gated ID. Every other active ID is still GREEN.

## Decisions a reviewer should know

- **The forced skip comes from the server, not the partner.** The rule "on
  `skipped`, one line, continue" is about skips that `next_step` reports, so the
  test exercises that path rather than having the partner decline a step.
- **The forced `down` is at the first enhancement.** This shows Claude stopping,
  and it means the run never pays for enhancements or compile. So compile is not
  exercised by real Claude.
- **One test fix after the red commit.** In `test_faults.py`, the
  required-step test walked into the enhance phase on an outline that still
  carries `down_at`, so it hit the down it wasn't testing. It now stops at the
  first draft and asserts the draft was handed out. That is the same claim; only
  the setup changed.
- **The spec has no ID for packaging.** Manifest, connector entry, and validator
  tests are unmarked. A `CONN-PLUG-03` for "the plugin validates and points at
  the connector URL" would be cleaner; that's the spec owner's call.
- **`license` is `UNLICENSED`.** The validator accepts it, but Anthropic's
  directory needs a real license or `LICENSE` file before listing.

## What was not tested

- **Real Claude has never run this.** CONN-PLUG-02 needs the deployed server
  (plan 2), so its cost and duration are estimates, not measurements. At Haiku 5.5
  prices ($0.10 / $0.50 per million input / output tokens under 100k-token
  prompts), a run of about 10 to 20 requests should cost well under $0.50. The
  report prints the measured tokens and an estimated cost.
- **The harness's API shapes are untested against the live API.** Block types,
  `pause_turn` handling, and the assumption that `mcp_tool_result` carries the
  server's JSON text all come from the docs page, not a live response.
- **The partner's "shown" test is a heuristic:** at least 300 characters that
  name the section.
- **Small models may vary.** Haiku might, for example, end its turn after
  each draft; the partner then says to carry on, and the cap absorbs it.
- **The plugin was validated but never uploaded** to claude.ai, and never
  installed in Claude Desktop.
- **The OAuth sign-in and consent screen** in the operator guide come from the
  spec and plan 3; neither is deployed.
- **Each real run leaves a `Fixture Co <timestamp>` deal in `test-firm`.** No
  archive tool exists yet.
