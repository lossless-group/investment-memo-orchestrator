```
feat(llm): route revise_summary_sections and key_info_rewrite through the provider
fix(corrections): a failed rewrite returns the original section, not an error string
fix(corrections): stop constructing an Anthropic client at import time

Both agents rewrite prose that already shipped — the bookend sections against
the assembled draft, and any section against a YAML correction file. Five call
sites across four modules remain, from 23 across 19 this morning.
```

## Why care?

`key_info_rewrite` had this at module scope:

```python
anthropic_client = Anthropic(api_key=os.getenv("ANTHROPIC_API_KEY"))
```

Not inside a function. At import. Any module that imports this one pays for a
client whether or not a correction is ever applied, and the key is resolved at
the moment of import rather than at the moment of use — which is the wrong time
for a pipeline that decides its provider per call.

It is a small thing that happens to be survivable here because a `.env` is
loaded early. It stops being survivable the moment someone imports this module
in a context that has no key, to call a function that never needed one.

## What changed

**Two agents routed.** `revise_summary_sections` (two calls — Executive Summary
and Closing Assessment, each against up to 50k characters of assembled memo) and
`key_info_rewrite` (one call per section per correction). **5 call sites across
4 modules** remain, from 23 across 19 this morning.

**A failed correction now returns the section unchanged.** `key_info_rewrite`
read the model's reply straight into `corrected_content` and wrote it to the
section file. Routed naively, a failed call would have written an empty string
over a finished section. The failure path returns `(original_content, 0)` — an
uncorrected section is a much better outcome than a destroyed one, and the count
of zero tells the corrections log nothing happened.

`revise_summary_sections` needed no such care: both calls already sat inside
`try/except` blocks that keep the existing section when revision fails.
