every firm the sign-in can use, and the connector version. A finished
imported deal gets a materials brief instead of a skip, and a step whose
read was skipped is told so in its inputs instead of getting nothing.

## Why Care?

On 2026-11-20 a partner of the first firm used the connector from a regular Claude chat. Five things got in the way, all recorded in `context-v/issues/First-Partner-Test-of-the-Connector-from-Claude.md`. `list_deals` cost thousands of tokens for 12 deals, a deal with no URL produced the sentence "The only correct company is at the company's website (not given)", a renamed company showed its former name, nobody could see which firm they were signed in as, and a research step on an imported deal reached Claude with an empty inputs list.

## What's New?

- **A lean `list_deals` (CONN-PT-01).** Each deal returns `skips_count` and `skips_by_reason` (each reason once, with its count). The per-skip `skips` list comes back only with the new input `include_skips: true`. An imported deal's 30-odd "Already applied in the local pipeline run…" skips are now one line.
- **A deal without a website asks for one (CONN-PT-02).** `render_instruction()` in `src/connector/flow.py` leads any step whose instruction names `{{url}}` with a fixed notice: ask the partner for the company's URL and don't research until you have it. `{{url}}` reads "its website (ask the partner)".
- **The trading name is the deal's name (CONN-PT-03).** `scripts/upload_firm.py` takes `company` from a new optional `trading_name`, then `name`, then `legal_name`, and keeps `legal_name` in `deal.json`. `list_deals` returns `legal_name` when it differs from `company`.
- **`whoami` (CONN-PT-04).** A read-only tool over MCP and `GET /v1/whoami`. It returns the account (subject, plus name and email when the sign-in carries them), the firm in use with its display name, every firm the sign-in can use with the active one marked, `firm_required`, and `connector_version`. A sign-in on several firms can call it without `firm`; it reports the firm chosen at sign-in. Tools that need the caller's identity declare `uses_principal` on their `ToolDef`.
- **Imported deals get a materials brief (CONN-PT-05).** For a finished deal the uploader no longer records `materials.brief` as skipped. It writes a brief listing the deal's materials, its finished memo version and the local run it came from. `research.section` reads only the brief, so its inputs were empty before.
- **A skipped read is never silent (CONN-PT-06).** When a step reads another step that was skipped, `gather_inputs()` adds an input with `skipped: true` naming the step and the skip's reason.
- **Spec and API changelog.** `whoami` has its row in §The tools and an inputs/outputs paragraph, `list_deals` documents its new fields, and the API changelog records 1.5.0. `SERVER_VERSION` is 1.5.0.

## Not Tested

- **Real id.didi.sh tokens.** `whoami` reads `name` and `email` claims when they exist; the tests mint tokens that carry them. Whether id.didi.sh's access tokens carry them hasn't been checked, and if they don't, `whoami` returns null for both.
- **The live server and a real partner.** Nothing was deployed. The plan's "partner repeats the first test in Claude" is still to do.
- **The first firm's real deal configs.** Engineers don't touch `io/`, so the known config whose `legal_name` is the company's former name still needs a `trading_name`, and the rest of the firm's configs haven't been checked for the same drift.
- **An unfinished imported deal with binaries.** Binaries are recorded as `ready` materials with no text file, so `next_step` on such a deal fails with `artifact_not_found` when it reaches `materials.brief`. This comes from the uploader change, not this plan, and isn't fixed here.

## Breaking for Clients That Read `skips`

`list_deals` no longer returns `skips` by default. The suite's own readers (`test_deals`, `test_enhancements`, `test_faults`, `test_materials`, and the real-Claude harness) now pass `include_skips`. A client outside this repo that reads `skips` must do the same. The plan asked for this default; the API changelog lists it under 1.5.0 rather than a `/v2/`.
