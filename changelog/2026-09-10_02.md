The README's agent table documented 27 of the graph's 35 nodes and omitted

than fix a table nobody regenerates, the counting moved into a script and the

## Why care?

You cannot fix what you cannot see, and for the last few months this repo could
not see itself.

Four documents claimed to say what the pipeline does. The README had two tables.
`docs/COMMANDS_CHEAT_SHEET.md` had a third. `WARP.md` had a fourth. Every one of
them was wrong, in different ways, and nothing in the repo could tell you that.
The most expensive consequence is not embarrassment — it is that an agent
opening this repo reads those tables and plans work against a pipeline that
stopped existing in November.

The concrete cost showed up last week. An open issue proposed a refactor across
nineteen files, with a hand-built table of where the work was. Two of its rows
were wrong. Nobody could have known, because checking meant counting twenty
files by eye — which is exactly the task that produced the wrong table.

## What changed

**`docs/PIPELINE-REFERENCE.md` is generated.** `scripts/gen_pipeline_reference.py`
parses `src/workflow.py` for nodes, edges, entry point and conditional branches;
`src/main.py` for flags; and `cli/`, `cli/utils/`, `src/cli/` for every tool's
docstring and arguments. It runs on the AST — no imports, no API keys, about
0.3 seconds. The output is 270 lines covering all **35** graph nodes in execution
order, ten `src/main.py` flags, and **41** CLI tools.

The eight nodes no reference table had ever mentioned:

```
aggregate_sources   fix_citation_spacing   attribution_audit   fact_verify
fact_correct        source_catalog         scorecard_nav       one_pager
```

`aggregate_sources` is the one that stings. It is the halt where an analyst
curates the source list — the seam the whole closed-corpus argument rests on —
and it was invisible in every document that claimed to list the agents.

**Judgement lives in `docs/pipeline-reference.overlay.yaml`.** A parser can read
node names and module paths. It cannot decide which resume stage a node belongs
to, which `AGENTS.md` principles bind it, or what a stage owns on disk. Those go
in the overlay and get merged at generation time. A node with no overlay entry
fails the suite — so the graph cannot grow a node whose documentation nobody
decided on.

**The stages are pinned to the six `--from` will accept**, named in
[[Agent-Sequencing-For-Deals-We-Already-Have-Content-On]]: `dataroom`, `deck`,
`research`, `write`, `assemble`, `export`. All 35 nodes are assigned. That work
is not built yet, but the taxonomy it needs is now written down and enforced
rather than living in an issue's prose.

**`tests/test_pipeline_reference.py`** — 14 tests. The doc must match the code;
every node needs an overlay entry with a stage and a purpose; every node must be
reachable from the entry point; every edge target must exist. We verified the
guards fire rather than trusting a green suite: adding a node, appending a
`ChatAnthropic(...)` to an unrelated agent, and hand-editing the markdown each
produced the expected failure.

## The scan that checked its own author

The generated inventory does one thing the tables never could: it counts the
modules that construct an Anthropic client directly instead of routing through
`src/llm_provider.py`. That is the live work-list for
[[Route-Every-Claude-Call-Through-The-CLI-First-Provider]].

It reproduced that issue's headline exactly — 19 modules, 24 call sites — and
then disagreed with two of its rows:

| File | Issue said | Actually |
|---|---:|---:|
| `socials_enrichment.py` | 1 | **0** — imports `ChatAnthropic`, never instantiates it. Tavily-only agent, dead import. |
| `citation_corrector.py` | 2 | **1** |

Then it got one wrong itself, and the way it was caught is the useful part.

After routing the deck analyst, the scan **still** reported that file as
bypassing. It was counting a comment — one written moments earlier, explaining
that the module no longer calls `Anthropic()`. The first scanner regexed raw
source. Prose about a call and a call look identical to a regex.

Chasing that turned up a second false positive: `portfolio_listing_agent.py` was
reported at 2 sites and has 1. Line 25 of that file is a docstring reading
`Anthropic (ChatAnthropic), similar to other agents` — a bare `Anthropic`,
whitespace, open paren. The regex counted it.

The scan now matches `ast.Call` nodes, which cannot see prose. Corrected
pre-refactor ground truth: **23 call sites across 19 modules**, not 24. The
issue records the mis-correction alongside the corrections, because the counting
method turned out to be part of the claim.

The dead import got [[Dead-ChatAnthropic-Import-In-Socials-Enrichment]] — a
one-line fix, filed because its cost is not runtime but a false entry on a
nineteen-module work list.

## Routing the deck analyst

The first step of the provider refactor, and the one the issue calls the hardest
case: four sites, the only image path, and the node that killed ProfileHealth
v0.0.4 with five raw 400s and no output.

| Was | Now |
|---|---|
| `Anthropic()` → page classification | `complete(prompt, images=[...])` |
| `ChatAnthropic()` + `llm.invoke` → deck text | `complete(prompt, timeout=_TEXT_TIMEOUT)` |
| `Anthropic()` → batched slide vision, 5/batch | `complete(prompt, images=[...], timeout=_VISION_TIMEOUT)` |
| `ChatAnthropic()` → section drafts | parameter deleted; helper calls `complete()` |

Three things this forced that the remaining eighteen files will not need.

**Images moved from bytes to paths.** Both vision paths base64-encoded renders
straight into an API payload. The CLI cannot be handed bytes — it reads images
with its own Read tool, from a directory granted via `--add-dir`. So renders now
land on disk through `_render_pages_to_files()`, and the API fallback re-encodes
from those same files. Both providers see identical input.

**The `llm` parameter was deleted rather than threaded.** A `ChatAnthropic`
instance was being passed into `create_initial_section_drafts` and
`create_section_draft_from_deck`. `complete()` is a function, not an object, and
nothing outside the module called either helper — so the parameter went away
instead of being reshaped.

**Vision needed its own timeout.** The CLI costs a Read round-trip per slide on
top of the completion. A 5-slide batch at the 300s extractor default would time
out in a way indistinguishable from a model failure. `_VISION_TIMEOUT` is 900s,
`_TEXT_TIMEOUT` 240s.

Proven live against a real deck rather than asserted:

```
deck: 2025-11__Blinka--Seed-Deck.pdf  pages=11
  rendered page-001.jpg 72 KB / page-002.jpg 127 KB / page-003.jpg 66 KB
calling complete() with 3 images ...
  elapsed=14.9s  ok=True  provider=cli
  parsed: {'company_name': 'blinka',
           'tagline': 'Making Commercial Real Estate Lending Automatic With AI Agents',
           'slides_seen': 3}
```

`provider=cli` — the subscription seat, not the metered API. Repo total moved
**23 → 19 call sites, 19 → 18 modules**.

Failure handling changed shape too. A batch that fails now names the provider
alongside the error and continues, so a run that loses every batch to a billing
problem says *billing* rather than `No batches were successfully analyzed`. A
failed section draft returns an `<insufficient-data />` marker rather than
apologetic prose — `AGENTS.md` §5.

## Written into the files agents actually load

A generated reference nothing points at is not canonical. So:

- **`CLAUDE.md`** — a *Regenerating the pipeline reference* subsection with both
  commands and a table of what changes force a regeneration; `Adding a New Agent`
  grew steps 7–10 (route through the provider, add the overlay entry, regenerate,
  green suite means wired *and* documented). Also corrected a live error: the
  entry point was documented as `deck_analyst` and has been `dataroom`.
- **`AGENTS.md`** — where the §-to-agent mapping lives, and both directions of
  keeping it true. Adding an agent means declaring its principles; renumbering a
  principle means grepping the overlay.
- **`README.md`** — a real section in the TOC, with the drift that motivated it
  named rather than glossed.
- **`docs/COMMANDS_CHEAT_SHEET.md`** — superseded banner. It documents none of
  `--firm`, `--deal`, `--fresh`, or `--frame`.

The suite is at **418 passed, 1 skipped**, up from 404.

## What is still open

The refactor continues with the single-call agents — `validator`,
`scorecard_evaluator`, `table_generator`, `link_enrichment`,
`visualization_enrichment` — one site each and mechanical now the pattern is
set. Then the writer and researchers, then `brand_fetch.py` last, after the CLI
is shown reachable from inside the FastAPI sidecar.

`KNOWN_BYPASSING` in the test is the ratchet: it fails on a nineteenth module
appearing, on a listed module growing a site, and on a module fixed but not
struck from the list. The number only moves down.

Still blocking the first framed run:
[[Agent-Sequencing-For-Deals-We-Already-Have-Content-On]]. The graph still starts
at `dataroom` every time. The stage taxonomy is now written down; the `--from`
flag that would use it is not built.

The README's two stale tables are still in the README, carrying notes that name
their own drift. Deleting them is a ninety-line edit to somebody else's front
door and is left as a decision rather than taken as a side effect.
