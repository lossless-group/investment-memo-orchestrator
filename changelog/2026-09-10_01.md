## Why care?

An investment memo is not written once. A company pivots, a partnership lands, a
new customer base appears — and the memo has to move with it. Until now that
meant opening ten section files and editing them by hand, which produces ten
independently re-angled sections that do not agree with each other.

The deeper problem was that re-running the pipeline was *worse* than editing by
hand, because it threw away everything the previous run had learned. Research
was regathered rather than extended. Hand-written sections were regenerated.
Every attempt to update a memo cost more than it recovered.

## What changed

**A thesis frame is a run variable.** `--frame <slug>` resolves a YAML file under
`frames/`, validates it against the active outline before spending anything, and
rides on `MemoState` exactly like `memo_mode`. No agent imports a frame file and
no prompt contains frame text as a literal, so adding a thesis is authoring YAML
rather than editing Python. Without `--frame`, the pipeline is byte-identical to
before: every injection point returns an empty string for a `None` frame.

**The frame injects in two places, not one.** An early draft threaded it into the
writer only. That is wrong — under a new thesis the *question behind a section*
changes, and the frame's evidence is usually absent from the corpus entirely. A
writer handed old research and a new frame writes confident prose over a stale
evidence base. `codified_section_researcher` now takes the frame too, and the
frame's questions are merged with the outline's rather than replacing them.

**Research accumulates. Prose is re-synthesised.** Both codified synthesis paths
ended in `write_text`, so research was additive only in the *instruction given to
the model* — the file itself was still being replaced. `write_or_append_research`
appends when a frame is active, the section's directive is `extend` or `refresh`,
and the file already has content; everything else writes as before. Appended
blocks carry `<!-- research-block: frame=… run=… appended=… -->`, which makes a
frame reversible: dropping a thesis means dropping its blocks rather than
re-deriving the file.

Directives are therefore two axes. Research is `extend` / `refresh` / `reuse`;
prose is `rewrite` / `amend` / `re-score` / `unchanged`. The pairing is the point
— grow the evidence, then re-synthesise over the union so a section reads as one
argument rather than an old draft with a new paragraph stapled on.

**`prose: unchanged` is the only thing protecting hand-authored work**, and the
writer now honours it, guarded on the file existing so "leave it alone" can never
mean "leave a hole in the memo".

**`amend` receives the prose it is amending.** The directive existed and was
tested, but the writer never passed it the prior section text — so "make the
minimum change" was silently behaving as a rewrite, discarding exactly the
sections it exists to protect. `rewrite` still never sees the old draft, or it
anchors on it.

**Frame evidence becomes a curated source before any section is researched.**
Documents a frame introduces are read into the same `fetched` corpus the codified
researcher fills from `Sources.md`, ranked ahead of the standing set, and tagged
only for sections whose directive actually researches.

**Video stopped being dead weight.** It was the one dataroom category always
reported and never used — `unsupported file type '.mp4'` — while being the
largest thing on disk. Media now parks in a gitignored directory and reaches the
pipeline as a transcript: hundreds of megabytes local, kilobytes committed, and
content the scanner can finally read.

**Oversized assets are normalized on ingest.** A scanned PDF at 19 characters of
text per page is rendered and OCR'd on every run from a document carrying far
more image data than OCR can use. Ghostscript at `/ebook` took one such file from
162 MB to 16.1 MB while the pipeline's own extractor OCR'd 2,417 characters
against the original's 2,415. Images do better than break even — `-auto-orient`
corrected a rotation that had tesseract reading a scan upside down. Originals are
parked untouched; nothing is destroyed.

**Exports stopped carrying their images.** `--embed-resources` inlines every
image as base64, which is 90% of a 17 MB memo. Images now upload to the CDN
through the same script the slide pipeline already uses, deduplicated by content
hash, with anything lacking alt text left embedded rather than published.

**The suite gained coverage measurement**, which it did not have. "282 tests
pass" said nothing about what was covered; it is now visible, and the suite is at
404 passed, 1 skipped.

## Four fixes that each would have destroyed prior work

These are worth naming individually, because each was silent and each was caught
only by checking rather than assuming.

1. **Version seeding.** `create_artifact_directory` makes an *empty* directory.
   The append path requires the research file to exist; the `prose: unchanged`
   guard checks the same empty directory. Both silently fell through to
   regeneration — the feature would have failed in exactly the way it exists to
   prevent, on its first real run, while printing that it was extending.
2. **Dataroom reuse after a killed run.** Extractor results are written as each
   completes so an interrupted run is not wasted, but the reuse check demanded
   `state.json`, written once at the very end. An hour of extraction sat on disk,
   current and complete, and unreachable. It now rebuilds from the artifacts.
3. **The normalization ledger, backfiring.** The byte discount was applied
   unconditionally, but an inventory may be recorded either side of
   normalization. Subtracting the discount from an already-normalized inventory
   manufactured a huge phantom gap and discarded the very analysis the ledger
   existed to preserve.
4. **The scanner walking the parking lot.** `_should_ignore` inspected only the
   filename, so the directory holding parked originals was walked like any other
   — offering the extractor two copies of every normalized document and
   reporting deliberately-parked files as unreadable.

Two older defects were fixed alongside: deck screenshot paths baked a version
directory into a deal-level cache, so every cache hit embedded the wrong
version's images; and the commentary sanitizer matched `**Note:**` but not
`**Note**:`, which is how a model refusal addressed to the operator shipped
inside a memo.

## What is still wrong

**The first framed run has never completed.** Three attempts; none reached the
researcher. Two issues, both written up, both blocking:

- [[Agent-Sequencing-For-Deals-We-Already-Have-Content-On]] — the graph runs
  every stage from the top on every invocation, and per-agent content-hash
  caching is the only thing between a re-run and an hour of re-extraction. Three
  separate caches were invalidated by ordinary maintenance in this session alone.
  Content-hash caching is not a resume mechanism. What is needed is an explicit
  entry point: nothing before it re-runs, entering at research adds only net-new
  sources, entering at writing does no web search at all.
- [[Route-Every-Claude-Call-Through-The-CLI-First-Provider]] — `llm_provider`
  tries the local seat and falls back to the metered API with a warning. Ten
  files use it; nineteen bypass it across 24 call sites, including the writer,
  both researchers, the validator, the scorecard and every enrichment agent.

Also unresolved and previously logged:
[[Validation-and-Fact-Checker-not-using-Research]] — the fact-checker reads a
legacy blob rather than the corpus the writer used, and treats a footnote in the
same sentence as the definition of "sourced". The validator sees only the memo
and a style guide, then scores a `sources` category.

Still unbuilt from the frame plan: `--scope-to-frame`, the `re-score` directive,
and wiring the commentary sanitizer into the graph at all — it remains reachable
only from a manual CLI.
