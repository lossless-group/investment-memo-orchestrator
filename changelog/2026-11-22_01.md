```
fix(upload): Record deal folders in history, and never send macOS metadata
```

## Why Care?

The server keeps a history of every change to a firm's memos, so a partner can see an earlier version of a section or undo an edit. A firm's first upload looked fine: every memo was on the server and served correctly. But the history entry for that upload held four files out of more than five thousand, and the deal folders were full of macOS `._` files.

Nothing a partner saw was wrong, but the next upload or revision would have built on a history with a hole in it. Both causes are fixed, and the next upload proved it: no `._` files, and an entry that holds everything.

## What's New?

- **Uploads record every deal they write** in the server's history (CONN-HIST-06).
- **No macOS metadata, from either end.** Staging skips `._*` and `.DS_Store`, the Mac packs without them, and the server deletes any that arrive anyway (CONN-UPL-05).
- **`check.sh` is green in worktrees.** Engineer subagents saw 25 false PDF failures in every worktree. It's fixed.
- **Logged for later:** a scorecard that recommends CONSIDER in justify-mode memos, and assembly listing cited data-room files as uncited Background Sources.
- **Planned:** drafting a memo from scratch in Claude, with `get_started`, suggested next steps, and materials registered by reference (CONN-START-01..04, CONN-REF-01..07).

## What Went Wrong

**The history entry.** We first guessed a timeout: the commit was huge, and history errors are logged rather than raised. A by-hand commit of the same 2,567 files took under a second, so that wasn't it. The real cause was one word. `JjHistory.record` names each path with jj's `root-file:` pattern, which matches exact files only. The uploader passes each deal as a folder, so every deal matched nothing, and only the loose firm files were committed. Folders now use `root:`, which takes everything under them.

**The `._` files.** macOS `tar` writes an AppleDouble entry beside any file with extended attributes unless `COPYFILE_DISABLE=1` is set. Staging already skipped hidden files in deal folders. The `._` files were created by the packing step, after staging. `apply` now sets `COPYFILE_DISABLE=1`, passes `--no-xattrs` and excludes both patterns, and `apply_upload.py` deletes any that reach the server.

**The false PDF failures.** In a worktree with a long path, uv writes the venv's `pytest` launcher as a `#!/bin/sh` script, and macOS strips `DYLD_*` whenever the protected `/bin/sh` starts. WeasyPrint then can't find pango. `check.sh` now runs `python -m pytest`, which keeps the variable.

## Under the Hood

- The affected firm's workspace was cleaned up once, by hand: 3,090 `._` files deleted, and the unrecorded changes committed as "upload 2026-11-21 (recorded late)". A second upload, run just before the fix was deployed, was also recorded by hand.
- `check.sh` on the merged tree: 879 passed, ledger 102 green.
