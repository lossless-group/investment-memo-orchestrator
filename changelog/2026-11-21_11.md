```
feat(citations): Key citations by their source, and number them only at render

Every source gets source_key(): sha256 of its first link (or its dateless
text), in base 36, six characters, eight where two sources collide. Keys are
assigned once per memo at assembly and compile, so numbered keys from older
runs convert and hex keys stay. consolidate_citations() and
merge_duplicate_definitions() dedupe by source and no longer renumber.

The connector's drafting steps ask for hex keys and say how to make one; a
new check refuses a hex key that isn't its source's and names the right one.
API 1.9.0.
```

## Why Care?

Each section's research numbered its sources from 1, so `[^25]` meant one source in the overview and another in the risks section. Stitching sections together linked claims to the wrong source ([[Final-Draft-Citations-Collide-Across-Sections]]). The assembler was patched to treat keys as local, but the cause was the numbering: a number is a position, not a source. Lossless Flavored Markdown already requires keys made from the source (rule 2), and now MemoPop writes them.

## What's New?

- **`src/citation_keys.py`.** `source_key()`, `source_identity()` and `assign_keys()`, shared with the repair tool. The identity is the first `http(s)://` or `file://` link (any case, percent-decoded, lowercased, no trailing slash), or the definition's text without its date.
- **Assembly and compile.** `consolidate_citations()` gives every cited source its hex key, assigned once over the whole memo. The block lists one definition per source in first-cited order. `merge_duplicate_definitions()` still merges two definitions of one source, but keeps keys. The final draft and the connector's `memo.md` keep hex keys; the exports number them.
- **The codified researcher** lets the model cite curated sources by number (the grounding check reads those numbers), then rewrites every key in code to the hex key of the curated URL. Research appended under a frame no longer collides with the research already in the file.
- **The writer prompt** says keys are hex codes and must be copied, never renumbered, renamed or invented.
- **The connector.** `research.section` (v3), `draft.section` (v3) and `draft.rewrite` (v2) explain how a key is made. If Claude can't run code, it uses placeholder letters and compile converts them, rather than guessing. `research.sources` and the enhance steps show hex keys. The new check `hex_keys_match_sources` refuses a six- or eight-character base-36 key that isn't its source's key, and names the right one. `SERVER_VERSION` 1.9.0.
- **Exports.** Pandoc numbers hex footnotes in first-cited order (tested). `cli/utils/restore_uncited_footnotes.py` reads hex labels and finds uncited notes by their inline references rather than by number.
- **`remove_invalid_sources`** only reorders keys of up to five digits, so an all-digit hex key is never renumbered.
- **Tests.** CONN-HEX-01..03 green. CONN-CMP-04 now asserts one hex key per source, as the spec was amended to say. One dedupe test asserts a shared hex key instead of a literal `[^1]`.

## What Isn't Tested

- **No real model run.** The codified researcher's Claude path and the writer's prompt changes have not been run against a model. The raw path is tested, and the Claude path uses the same rewrite.
- **No real Claude session on the connector.** The new step text, including the placeholder-letter fallback, is checked for its wording only.
- **The other research agents** (Perplexity researcher, citation enrichment, fact corrector) still number their citations. Assembly converts those keys, but these agents were not changed or run.
- **Branded PDF exports.** Only plain Pandoc numbering is tested. `cli/export_branded.py` was not run on a hex-keyed memo.
- **Semantic keys** of exactly six or eight lowercase letters or digits (a hand-written `[^survey]`, say) look like hex keys, so the new check refuses them. Nothing in the repo writes such keys today.
- **Finished memos** are not rewritten here. That is the repair tool's job (Part 1).
