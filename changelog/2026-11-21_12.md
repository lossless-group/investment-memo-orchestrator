```
feat(preview): Render previews and exports with LFM on the server

A Node script pinned to @lossless-group/lfm 0.11.0 renders markdown to HTML
in two steps, so callouts and hex-code citations aren't skipped; citations
are numbered in first-cited order and the sources list comes from LFM's
ordered citations. Python calls it as a subprocess, as it calls pandoc.

New read-only tool preview (GET /v1/deals/{deal}/preview?artifact=) renders
a section, the assembled memo, or any artifact inside the firm's branded page
and returns a signed link and the HTML, before or after compile. compile's
HTML and PDF use LFM when MEMOPOP_EXPORT_RENDERER=lfm (default pandoc), and
cli/export_branded.py takes --renderer lfm. The server's instructions and a
preview-a-memo playbook tell agents never to render a memo themselves.
API 1.10.0.
```

## Why Care?

Three renderers showed one memo three ways: Pandoc for local exports, Pandoc again for the connector's exports, and LFM on the firm sites. A partner working through Claude had no way to see a draft as it would look, and an agent that rendered the markdown itself made a fourth version, with citation numbers of its own. Now the server renders once, with LFM, and every agent is told to use that ([[Render-Previews-and-Exports-with-LFM]]).

## What's New?

- **The renderer.** `src/connector/render/lfm_render.mjs` reads markdown on stdin and prints the HTML body. It runs `parseMarkdown`, then `remark-rehype` and `rehype-stringify`, as two steps: chaining `remarkLfm` and `remarkRehype` in one processor silently skips callouts and citations. Citations are numbered from the hex keys in first-cited order, and the sources list is rendered from `tree.data.citations.ordered` under the memo's Citations heading. Callouts keep their titles. It imports LFM's `/browser` entry, so a render makes no network calls. `package.json` pins `@lossless-group/lfm` 0.11.0 and its three helpers exactly, with a lockfile.
- **The Python side.** `src/connector/render/lfm.py` calls the script as a subprocess. Without Node, or without the package, it says which is missing (and `npm ci --prefix src/connector/render` for the package). The connector turns either into `service_unavailable`.
- **`preview`.** A new read-only tool, `GET /v1/deals/{deal}/preview?artifact=…`. `artifact` is a section (key, name or number) for its current text, `memo` for the whole memo assembled from the current sections as compile would (no version saved), or any artifact id (`compile.assemble` is the last compiled memo). It returns `html_url`, a signed link valid for seven days, and the `html`. The page is the firm's branded page with LFM's body; it is stored under `previews/<deal>/` in the firm's bucket and nothing in the deal changes.
- **Exports.** `MEMOPOP_EXPORT_RENDERER` chooses compile's renderer: `pandoc` (the default, unchanged) or `lfm`. Either way the firm's brand CSS from `brand-<firm>-config.yaml` styles the body, and the PDF is printed from that HTML. `cli/export_branded.py --renderer lfm` does the same for local exports, inlining local images since Pandoc's `--embed-resources` is out of the loop.
- **Agent instructions.** The MCP server's instructions say to call `preview` and give the partner its link, and never to render the markdown or invent citation numbers. A new `preview-a-memo` playbook; `compile-and-check-the-site`, `rewrite-a-section-from-its-research` and `edit-wording` point at it. `SERVER_VERSION` 1.10.0.
- **The image.** The Dockerfile installs the renderer's packages with `npm ci` in a Node 22 stage and copies `node` and `node_modules` into the runtime image; the build renders a test citation. CI installs Node 22 and the packages before the check ladder.
- **Tests.** CONN-LFM-01..06, all green: numbering, pinning, missing Node or package, the setting, the CLI option, `preview` over direct calls, REST and MCP, and the instructions and playbooks.

## What Isn't Tested

- **LFM exports against each firm's brand.** The default stays `pandoc` until a partner compares an LFM export with the pandoc one. Firms whose brand config names a `theme` render locally with pandoc only; `--renderer lfm` uses the brand CSS for them.
- **No real Claude session** has called `preview`; the instructions are checked for their wording only.
- **Not deployed.** The image was built and the renderer run inside it locally; Railway has not run it.
- **Uncited definitions** are left out of LFM's sources list (Pandoc's local export restored them).
