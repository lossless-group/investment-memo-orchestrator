```
fix(citations): Key appended research blocks by source, and read old ones block by block

An appended research block numbered its footnotes from 1 again, so one
research file defined [^1] once per block and assembly linked the reused
block's footnotes to the appended block's sources. Appends now re-key the
new block to hex keys (a source the file already defines keeps its key).

Assembly and the repair tool share src/research_blocks.py: split research at
each appended block, read section part i against block i, and refuse only a
key two blocks define differently. Repair pairs markers on unedited lines
when a region no longer pairs as a whole, and reports counts per reason.
The scan tells appended blocks from collapsed keys.
```

## Why Care?

When a run reuses a version's research and adds new sources, the new findings are appended under `## Added from N new sources`. That block numbered its footnotes from 1 again, so one research file defined `[^1]` twice for two sources, and assembly kept the last one. In one memo a third of the footnotes, including every team bio, linked to a source from the appended block instead of their own ([[Appended-Research-Blocks-Reuse-Footnote-Keys]]). This affected memos assembled after the hex-key change too, because the lookup happens before keys are assigned. The repair tool refused these files outright, and the scan mistook them for the older collapsed-keys bug.

## What's New?

- **Appends re-key the new block** (`rekey_appended()` in `src/research_append.py`, for both the augment and the thesis-frame paths). Each source in the block gets its hex key from `src/citation_keys.py`; a source the file already defines keeps the key it has there, and its duplicate definition is dropped. A research file now defines each key once. Hex keys rather than continued numbering: they are the keys assembly gives sources anyway, need no count of the keys above, and can't collide with numbered or hex keys already in the file.
- **`src/research_blocks.py`**, shared by assembly and repair. It splits a research file at each block's stamp or `## Added …` heading, and a section at its `### Added …` headings. With one section part per block, part *i* reads block *i*; otherwise a key is read in the block that defines it. A key two blocks define with different sources, with no part to say which, is refused rather than guessed.
- **Assembly** (`assemble_citations`) reads research files with appended blocks this way, in memory. A refused key is left unlinked, printed, and listed in the stats as `refused_keys`. Files without appended blocks assemble exactly as before.
- **The repair tool** (`src/citation_repair.py`) decides footnote by footnote. A region that still pairs one for one with its section file is paired as before; otherwise markers are paired only on lines whose prose is byte-identical to the section file, so a few edited lines no longer block a whole section. Regions can now be `partial`; each carries `repaired`, `refused` by reason and `refused_keys`, and `repair-report.json` sums them under `counts`. A key one block defines twice is refused on its own in a file with appended blocks; a file without appended blocks that defines a key twice is still refused whole. Prose still never changes.
- **The scan** flags "appended blocks reuse keys" separately from "collapsed keys".
- **The `repair-memo-citations` skill** explains blocks, partial regions and the new refusal reasons.
- **Tests.** CONN-HEX-04..08 green (`tests/test_appended_research_blocks.py`, synthetic fixtures). Existing repair, assembly, append and thesis-frame tests unchanged and green.

## What Isn't Tested

- **No memo was rewritten.** The tool was dry-run against three real memos (counts in the issue's Resolution); no `--write` was run on firm files, and none were re-exported.
- **No real run with an append.** The re-keying is tested on synthetic files, not in a full pipeline run that reuses research.
- **The connector is unchanged.** It doesn't read research files with appended blocks, so no API version change.
