## Why Care?

A memo is only as good as what it reads. When a company hands over a dataroom, that dataroom is the best evidence the pipeline will ever see, yet the Sources draft that the analyst curates was built from web search alone. The dataroom was read elsewhere, but it never appeared on the list the analyst approves. Now it opens the list.

The second fix is smaller and more visible. An exported memo showed whole paragraphs as giant headings. That wasn't a long heading the writer chose: it was a Markdown quirk, and the pipeline itself was triggering it.

## What's New?

- **Dataroom first.** The aggregated Sources draft now starts with a "Dataroom" block: every document from the dataroom inventory, already `verdict: approved`, carrying its `local_path` and mapped to the sections it informs. Decks come first, then SAFEs and term sheets, then cap tables, then everything else.
- **But not the paperwork.** Corporate housekeeping such as incorporation documents, stockholder and board consents, purchase and subscription agreements, side letters and wire instructions is left out. A draft memo doesn't need it, and it would crowd the list. Product, team, market and financial material all stay in.
- **`***` is the only section break.** A `---` line anywhere other than the opening frontmatter can be read as a frontmatter delimiter. Directly under a paragraph it is a setext heading underline, so the whole paragraph becomes an H2. Every writer in the pipeline now emits `***`.

## How it Works

The heading bug came from the reuse-and-augment path. When a re-run finds new sources for a section, it synthesizes just those and appends them to the existing research beneath a rule. The rule was `---`, written straight after the previous paragraph. When the writer carried that block into a section draft, the paragraph above it rendered as a heading in the export.

The fix has three layers:

1. **Writers** use `SECTION_BREAK = "***"` (about twenty call sites, from research appends to the TOC, citation blocks, scorecards and dataroom reports). Code that writes YAML frontmatter still writes `---`.
2. **Readers** that look for a break (the TOC locator, citation stripping, the scorecard navigator, the themed export, the internal-notes splitter) accept either spelling, so artifacts from earlier runs still parse.
3. **A backstop** for text an LLM wrote: `normalize_section_breaks()` rewrites any `---` break as `***` with a blank line above it. It leaves the opening frontmatter, fenced code and table delimiter rows alone. It runs where sections, research files and final drafts are written, in the late citation-spacing pass, and in `export_branded.py`, so re-exporting an old memo fixes it without a re-run.

The rule also lives in the `lossless-flavored-markdown` skill as rule 6, since it applies to every markdown file in the tree, not just memos.

## What's Next

- The citation validator still treats dataroom `file://` citations as invalid; it should accept them and render them as named dataroom documents.
- Augment blocks ("Added from N new sources") can still be carried from research into a section draft as a second write-up. The writer should merge new evidence in rather than copy the block.
