## Why care?

Plan 1 got a deal as far as its drafts. This is plan 5 of the connector spec
(`context-v/specs/MemoPop-Connector-API.md`): the rest of the method. After it, a
scripted client walks a deal from `create_new_deal` to a compiled memo over MCP
and over REST, and the memo is the one a partner would hand to their investment
committee: sections in outline order, the enhancements folded in, one citation
list, a table of contents, and a branded PDF.

## What landed

**Seven enhancement instructions, plus research.sources.** Each step's interim
text is replaced by one adapted from its source agent: tables, diagrams,
citations, fact check (with the attribution audit and corrector's rules),
scorecard, summaries, and one-pager. Every model and API call is gone, and each
says exactly what to submit and how to skip. Tables, citations, and fact check
submit the whole revised section. Steps read a new `section.current`, the latest
version of each section, so the revisions chain on one another instead of each
starting from the draft.

**Skips, end to end.** An operator switch (`MEMOPOP_DISABLED_STEPS`, or
`enabled: false`) skips an optional step with `step_disabled`. A compile stage
that raises is skipped with `step_failed`, and the memo is still made. Claude can
now skip an optional step itself: `submit_artifact` with `skip: true` and a
one-sentence `reason` records `step_skipped`. Required steps can't be skipped.
Every skip appears once in `next_step`'s `skipped_since_last_call`, and in
`list_deals` and compile's report.

**`compile`.** It runs the spec's server steps with no model, reusing the
existing agents through pure functions extracted beside them (see Decisions):

1. It gathers each section's current text, swaps in the revised summaries, and
   appends the scorecard.
2. It consolidates and renumbers the citations, fixes their spacing, adds the
   table of contents, places deck images, and draws the TAM/SAM/SOM diagram
   from the data Claude submitted.
3. It renders branded HTML (pandoc) and a PDF (WeasyPrint).

The memo's markdown is the `compile.assemble` artifact, so `get_artifact` reads
it. The exports go to the firm's bucket under `compiled/<deal>/<version>/`.
Compile returns links that expire in seven days: S3 presigned in production, an
HMAC-signed `/v1/files/` route for local buckets. Sections that haven't changed
compile to the same version.

Past `MEMOPOP_COMPILE_BUDGET_SECONDS` (default 200), compile returns a `job_id`.
`list_deals` then shows the job's status and, once it's done, fresh links. A
deal with an undrafted section is `drafts_incomplete`.

**The scripted client** (`tests/connector/fake_claude.py`) does what the skill
will tell Claude to do: call `next_step`, submit the canned artifact (approved
when the step needs the partner), or skip it, until done, then compile. The same
walk runs transport-free, over MCP, and over REST.

**Ledger:** all nine plan 5 IDs went from RED (none missing) to GREEN, and all
42 IDs of plans 1 and 5 are green. `scripts/check.sh` passes: 596 passed, 10
skipped.

## Decisions a reviewer should know

- **Where enhancements land in the memo.**
  - Tables, citations, and fact check produce whole revisions, and the latest one
    replaces the section.
  - Summaries replace the sections whose headings they repeat.
  - The scorecard follows the last section.
  - Diagrams submits only data (a fenced YAML block, checked by the new
    `fenced_yaml` check), and the server draws the TAM/SAM/SOM bubble with the
    existing matplotlib renderer as an inline SVG.
  - The one-pager is saved beside the memo, not inside it.
- **Compile's internal stages are not registry steps.** The spec maps
  `compile.assemble` to one step. Its optional stages (`compile.spacing`,
  `compile.toc`, `compile.deck_images`, `compile.diagrams`) carry ids so they
  can be disabled and reported. They live in `compile/pipeline.py`, which keeps
  the registry equal to §First mapping.
- **Agents reused, not copied.** Three new pure functions sit beside their
  originals, and `gen_pipeline_reference.py --check` passes:
  - `citation_assembly.consolidate_citations` treats each section's keys as
    local. `renumber_citations` treats them as global, which would merge two
    sections' different `[^1]`s.
  - `diagram_generator.insert_after_first_paragraph`.
  - `export_branded.render_branded_html`, which is in-memory, doesn't look
    anything up in `io/`, and embeds no remote resources.
- **The time budget is 200 s, not the spec's 240.** The plan asked for 200 so a
  job comes back well before the spec's 240-second promise. The docs say "about
  200 seconds".
- **Only text goes in the workspace.** `memo.md` and `report.json` are written
  under `compiled/<version>/`; the HTML and PDF go only to the bucket.
- **New error codes** (additive): `drafts_incomplete`, `link_expired`, and
  `step_skipped`. Server version 1.2.0.
- **`scripts/check.sh` sets `DYLD_FALLBACK_LIBRARY_PATH` on macOS.** WeasyPrint
  loads pango and gobject by bare name, and macOS strips `DYLD_*` when it starts
  `/bin/bash`. Plain `uv run pytest` on a Mac without that variable fails the 21
  tests that make a PDF; CI (Ubuntu, apt libraries) doesn't need it.

## What was not tested

**Deck images.** The deck-image stage has no test that places an image. Its
input contract, `materials/deck-images.json`, is my guess at what phase 4's
extraction will write, and phase 4 has not been reconciled with it. With no file
the stage does nothing.

**Materials in the walk.** The `fixture-co` walk has no deck PDF or notes, so
the walk never hands out `materials.brief`. CONN-ENH-02's `materials.brief` case
injects a synthetic ready material straight into `deal.json`, in a shape that
may not match phase 4's.

**S3 links.** S3 presigned links were never exercised; only the local-bucket
route was.

**Firm branding.** No firm brand config was tested. Logo paths in a firm's
config resolve against the working directory, as `export_branded` always has.
Google Fonts links in a brand would make WeasyPrint fetch them at PDF time.

**Restarts and concurrency.**
- A compile job is a thread in the process, so a restart mid-job leaves it
  `running` until it is an hour old, when a new compile starts afresh.
- Two compiles started in the same instant on one deal are not prevented. Only
  a compile that has already been recorded as running is deduplicated.
- The link secret is random per process unless `MEMOPOP_LINK_SECRET` is set, so
  local links die on restart.

**History.** Nothing ran against phase 6's jj history. Each compile records one
history entry, with `memo.md` and `report.json`.

**Real Claude.** No model has followed the new instructions; they are untested
prose until plan 7.
