## Why care?

The fact-checker extracts claims, the attribution auditor flags the ones about
the wrong company, the fact verifier checks them against sources — and then
`fact_corrector` decides whether any of that reaches the memo.

It opened with this:

```python
anthropic_key = os.getenv("ANTHROPIC_API_KEY")
if not anthropic_key:
    print("⊘ Fact correction skipped - no ANTHROPIC_API_KEY")
    return {"messages": ["Fact correction skipped - no Anthropic API key"]}
```

On a seat-only run, every correction the pipeline had just computed was
discarded at the last step. The line prints, but it prints inside a run that
emits hundreds of lines, and the memo that comes out the other end looks
finished. This is the third guard in two days that turned a feature off exactly
when the CLI-first path was doing its job — after the five `ValueError`s in
[[2026-09-10_03]] and codified mode's own switch in [[2026-09-10_04]].

## What changed

**Three agents routed** — `citation_corrector` (2 sites), `fact_corrector`,
`source_extractor`. **7 call sites across 6 modules** remain, from 23 across 19
this morning.

`CitationCorrectorAgent` used to build its client in `__init__` through a factory
that raised without an API key, so the object could not even be constructed on a
seat-only machine. It now holds a model id and nothing else.

`source_extractor`'s `_extract_one()` took a shared `llm` as its first argument
and was fanned across a six-worker pool. There is nothing to share now — each
call is independent, which is what the pool wanted in the first place.

## A race six threads wide

That pool is the first place in this codebase to make six model calls at once,
and routing it exposed something the sequential callers never could.

`_isolated_dir()` lazily creates one empty directory to run CLI calls from —
empty on purpose, because a working directory containing `CLAUDE.md` files loads
all of them into every request, about 26k tokens' worth. It assigned a module
global with no lock:

```python
global _ISOLATED_DIR
if _ISOLATED_DIR is None or not _ISOLATED_DIR.exists():
    _ISOLATED_DIR = Path(tempfile.mkdtemp(prefix="memopop-llm-"))
    (_ISOLATED_DIR / "empty-mcp.json").write_text(...)
```

Two threads can both read `None`, both `mkdtemp`, and one assignment wins. The
loser's directory leaks — and worse, the winner publishes the path *before*
writing `empty-mcp.json`, so a third thread can read the global and pass
`--mcp-config` for a file that does not exist yet.

Now under a lock, with the path published only after the config is written.

Verified live at the shape the pool actually creates:

```
call 0..5: ok=True provider=cli
elapsed=3.4s for 6 concurrent calls
isolated dir: /var/folders/.../memopop-llm-8ey9l91q     <- one, not six
```

and pinned by a test that puts eight threads through a barrier and asserts
`mkdtemp` ran exactly once. Removing the lock turns it red, which was checked
rather than assumed.
