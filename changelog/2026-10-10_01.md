## Why care?

This is our first API, and plan 1 of the connector spec
(`context-v/specs/MemoPop-Connector-API.md`). After it, a partner's Claude can
connect to `/mcp`, sign in with an id.didi.sh access token, start a deal, and be
handed the MemoPop method one step at a time: research each section, show it to
the partner, submit it approved, then draft each section from the approved
research. The server owns the order, keeps every artifact, and refuses to draft
what the partner hasn't approved. Plans 4, 5, and 6 (materials, compile,
history) now build on this in parallel.

## What landed

**The ledger and the ladder.** `src/ledger.py`, `scripts/spec_status.py`, and the
marker hooks in `tests/conftest.py`, copied from corpora-builder and adapted (a
Tests section ends only at a `##` heading; `--plan` and `--active-plans` check a
plan's owned IDs alone). `scripts/check.sh` runs ruff and black on the new code,
the whole suite, then the ledger with `--require-green` for every plan In Progress
or Shipped. All 33 of plan 1's IDs are GREEN; they were all RED, none missing,
at the TDD-floor commit.

**The registry** (`src/connector/registry/`): all eight tools declared with every
docs field, `readOnlyHint` and `destructiveHint` per the spec; all thirteen steps
from the spec's first mapping, one markdown file each in `src/connector/steps/`.
`research.section` and `draft.section` carry instructions adapted from
`perplexity_section_researcher.py` and `writer.py`, with every model call removed.
The other Claude steps carry interim instructions that plan 5 replaces.

**Five tools work**: `list_deals` (keyset-paged, limit capped at 100),
`create_new_deal` (slug from the url's domain, idempotent by slug, domain, or
name), `next_step`, `submit_artifact` (checks, versioning, identical content is a
no-op, approval gates drafting), and `get_artifact` (paged at 100,000 characters;
`next_step` cuts its inputs to stay under 150,000). `add_materials`,
`save_snapshot`, and `compile` return `not_implemented` until their phases land.

**Transports.** MCP via the official SDK (stateless Streamable HTTP, JSON
responses) at `/mcp`, and REST under `/v1/`, both over one transport-free
`invoke()`, so their bodies are identical. Checked against the SDK's own client
over uvicorn as well as in tests.

**Auth.** id.didi.sh access tokens verified exactly as that service mints them:
EdDSA, `typ: at+jwt`, `iss` `https://id.didi.sh`, `aud` `https://memopop.didi.sh`
(or `.../mcp`), firm from `entity.slug`. Interim static per-firm keys
(`MEMOPOP_STATIC_KEYS`) for Claude Code and the health check. The
protected-resource document is served at both well-known paths with resource
`https://memopop.didi.sh/mcp`, built from the configured base URL so a proxy
can't make it http.

**Docs, generated.** `/v1/openapi.json` (validated as OpenAPI 3.1), `/llms.txt`,
`/llms-full.txt`, `/docs`, `/docs/errors`, `/docs/changelog`. Every docs example
is executed by the tests.

**Storage.** Workspaces under `MEMO_IO_ROOT` with transactional writes (a failing
disk rolls everything back), per-deal locks, a local and an S3 bucket behind one
interface, and the no-op `History` hook phase 6 fills with jj.

## Decisions a reviewer should know

- **CI and the io-dependent tests.** CI checks out without submodules. The
  blocking step is `scripts/check.sh`: the whole suite except
  `tests/test_amend_on_polish_path.py` (its 7 tests read private `io/<firm>` data
  and error without it), plus the ledger. A second, non-blocking step runs that
  file alone so its state is reported, not hidden. With `io/` present,
  `check.sh` runs it too.
- **Swagger moved.** The spec gives `/docs` to the connector, so the sidecar's
  FastAPI Swagger UI moved to `/sidecar/docs`. The 22 sidecar routes are
  unchanged.
- **`not_implemented`** joins the error catalogue (additive, `invalid`, HTTP 400)
  for the three tools whose phases haven't landed.
- **Approval on identical content.** Resubmitting identical research with
  `partner_approved: true` records the approval without a new version; that is
  the only way identical content changes anything.
- **Firm provisioning** is an operator act: a firm's workspace is a directory
  under `MEMO_IO_ROOT` with an optional `firm.json` (`default_template`,
  `entity_id`). A valid token for a firm with no workspace gets `forbidden_firm`.

## What was not tested

Nothing here talked to a real id.didi.sh: tokens come from a locally generated
Ed25519 key and a JWKS served through a mock transport, shaped to match what that
service mints, so a mismatch with the live issuer (a claim name, the `typ`
header, key rotation) would only show up against its staging (spec layer 9).
The S3 bucket implementation has no test at all; only the local-directory bucket
is exercised, and nothing in plan 1 writes to a bucket yet. Nothing was
deployed, and no real Claude client (Desktop, claude.ai, or the API's MCP
connector) has called the server; the closest is the MCP SDK's own Python client
against a local uvicorn. Concurrency is covered by design (thread lock plus
flock per deal), not by a test that races two writers. The interim step
instructions for materials, sources, and enhancements have never been run by a
model.
