```
feat(connector): Notify the firm's site when a memo compiles

A firm's site reads each memo from MemoPop on every page view, so a
partner's compile shows after a refresh, at the cost of a round trip per
view. Now MemoPop tells the site when a deal's memo changes, so the site
can cache the memo and drop one deal's copy when told.

After a compile saves a new version (or new exports), and after the
uploader's apply step changes a deal's compiled version, MemoPop POSTs a
memo.compiled event to firm.json's site_hook_url: firm, deal, version,
label and compile time, signed with HMAC-SHA256 over
"<timestamp>.<raw body>" with the firm's site key. No memo text, no links.

Sending runs on a background thread and never delays or fails the compile.
A timeout, connection error or 5xx is retried after 1, 5 and 25 seconds; a
4xx is not. Logs carry firm, deal, status and duration, never the key or
the signature. No site_hook_url or no site key, no request.

Also included: the plan, the HOOK rows in the connector spec's tests, and
the firm.json site fields in the operator deploy doc.
```

## Why Care?

Measured on 2026-11-21, a firm's memo page spent 0.2 to 0.45 s fetching a 109 KB memo from MemoPop on every view. Caching the memo on the site removes that, but a plain cache would show the old memo after a compile until it expired. With a notification, the site caches until MemoPop says the deal changed, so pages are fast and the partner's "compile, then refresh" loop still works.

## What's New?

- **`src/connector/site_hook.py`.** Builds the event, signs it, sends it with a 5 s timeout and backoff, and logs each attempt. Uses `httpx`, already a dependency.
- **`compile` notifies** after the compiled record, memo and history entry are saved. A compile that changes nothing sends nothing; a failed or refused compile never gets that far. A compile that outlasts its time budget notifies when its worker finishes.
- **The uploader's apply step notifies** for each deal whose compiled version or hash differs from what the server had, after the upload is recorded in the firm's history, then waits up to 90 s for the sends before the script exits.
- **`firm.json` gains `site_hook_url`**, beside `site_memo_url` and `site_memo_slugs`, documented in `docs/operator/deploy.md` and the connector spec's §Site read endpoint.
- **Tests:** `tests/connector/test_site_hook.py`, CONN-HOOK-01 to 06, against a fake endpoint with the backoff recorded instead of slept.

## Not Tested

- **No real site.** Every request went to an `httpx.MockTransport`. No site has a hook endpoint yet.
- **The apply script end to end.** The tests call its `replace_deals` and `notify_site`; `main()` (backups, bucket, history) wasn't run.

## What's Next

- Deploy to the `connector` service, then set `site_hook_url` in a firm's `firm.json` once its site's hook endpoint and cache are live.
- The site side (hook endpoint, signature check, per-deal cache with a 3-day ceiling) is built in each site's repo.
